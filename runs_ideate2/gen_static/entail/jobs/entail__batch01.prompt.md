### proposal: relocated_bindings_demand
Title: Relocate the Mug: Binding Demand and Binding Supply, Not Bank Content, Decide Whether Experience Retrieval Beats a Compiled Procedure
Short Hypothesis: On template environments the retrieval gain is procedure-bound because nothing instance-specific is both required for success and unguessable from priors; if the environment is edited so that the target object sits off its canonical receptacle (relocated PDDL initial state) and search is expensive (tight step budget), a scene-keyed retrieval residual over the best static prompt appears, but only when the bank contains a same-scene item carrying the new location, and a cached location table with one row per (scene, object class) recovers the same residual at zero uncached tokens.

Experiments:
1. Construction: for each of the 274 eval games (valid_seen + valid_unseen) compute the canonical receptacle set of the target class from train (receptacles holding the class in >=5% of train games); relocate the object (both objects for pick-two) to a type-compatible, non-goal receptacle in the same scene outside that set, deterministic per (scene, class); edit the PDDL problem init; run the ALFWorld PDDL expert to verify solvability and to produce the fresh expert trajectory; drop and count games the planner cannot solve. Apply the same rule to all train games in the eval scenes to obtain the sibling supply (fresh relocated expert items). 2. Manipulation check (first, positive control): k=0 at canonical x {50, 25} and relocated x {50, 25}, 274 x 2 seeds each. Pre-registered escalation: if relocated x 25 does not drop k=0 success by >= 8 net vs canonical x 25, run one further level (budget 15 or +10 distractor objects in closed receptacles); if still no drop, stop and report the demand lever as inert. 3. Confirmatory cells (each arm 274 x 2 seeds, ~30 min): relocated x tight x fresh-sibling supply: goal-query k=3, scene-query k=3, type-agnostic static, compiled table, type-conditioned 3 exemplars, placebo; canonical x tight: goal-query, scene-query, type-agnostic; relocated x loose x fresh supply: scene-query, type-agnostic; relocated x tight x scene-disjoint supply: scene-query. 4. Exploratory: relocated x tight x stale-sibling supply (scene-query) for the compliance-trap direction; whole-bank arm at relocated x tight x fresh supply; per-type breakdown (clean/heat/cool vs pick-and-place vs pick-two vs look-at). 5. Cost: prefill tokens per episode split into cached (static prefix, vLLM prefix cache hits) and uncached (retrieved items), plus retriever wall-clock; accuracy-cost curve per cell. Total ~8,500 episodes, ~7-8 h at 20 episodes/min on two A100s (one vLLM replica per GPU).

Baselines and Ablations:
Baselines (static, cached): type-agnostic all-six-procedures prompt (~400 tokens); type-conditioned 3 fixed expert exemplars (~430 tokens, matched to k=3); compiled location table (procedures + <=274 rows); random-type 3-exemplar length placebo; whole-bank 80-item arm (~11k tokens) as the no-query information-complete arm. Retrieval arms: goal-query k=3 (Measurement A retriever, unchanged) and scene-query k=3 (same embedding model, index text = goal + first observation). Ablations: supply (fresh sibling / scene-disjoint / stale sibling); demand (canonical/relocated x 50/25 steps); k=1 and k=7 for the scene-query arm at the positive cell; table with rows shuffled vs sorted by scene (lost-in-the-middle check); table restricted to the 20 rows of the current scene's classes (a cheaper compiled variant); second seed pair to check seed stability of the positive cell.

Falsifiable Predictions:
P1 (positive control) k=0 success at relocated x 25 steps is >= 8 net below canonical x 25 steps. Falsified if the drop is < 8 net; produced by the two k=0 cells. If falsified after the pre-registered escalation the demand lever is reported inert and the confirmatory cells are not run. P2 (no residual without demand) In canonical x 25 and in relocated x 50, scene-query retrieval minus type-agnostic static is <= +8 net. Falsified by a residual >= +8 in either cell (produced by the canonical x tight x scene-query cell or the relocated x loose x scene-query cell), meaning the residual is not gated by demand. P3 (residual with demand and supply) In relocated x 25 x fresh-sibling supply, scene-query retrieval minus type-agnostic static is >= +14 net (half the Gate-0 gain of 27). Falsified by < +8 net in that cell, meaning the reader cannot apply a location from a retrieved trajectory even when required (application failure, G7). P4 (binding-bound, not content-bound) In relocated x 25 x scene-disjoint supply, scene-query retrieval minus type-agnostic static is <= +8 net. Falsified by >= +8 in that cell, meaning the residual comes from non-binding content of retrieved trajectories (e.g., a search heuristic) rather than the binding. P5 (the query matters only under demand) In relocated x 25 x fresh supply, scene-query minus goal-query retrieval is >= +8 net, and in canonical x 25 it is within +-8. Falsified by scene-query minus goal-query < +8 in the relocated cell (goal similarity already keys the sibling through class-scene correlation) or >= +8 in the canonical cell; both cells exist. P6 (compilability) In relocated x 25 x fresh supply, compiled table minus scene-query retrieval is >= -8 net. Falsified by table < retrieval - 8 in that cell, meaning the reader can use a 430-token trajectory but not a 3k-token table, so the query is necessary at 274 rows. Exploratory (declared, not confirmatory): whole-bank 80-item arm is <= scene-query retrieval - 8 (the sibling is not found among 80 items); falsified by whole-bank >= retrieval - 8 in the whole-bank cell. Stale-sibling supply gives retrieval <= type-agnostic static - 8; falsified by retrieval >= static - 8 in the stale cell.

Measurement and Noise Control:
Primary outcome: task success on the same (game, seed) pairs across arms; nets in points; paired differences with a cluster bootstrap over games (1,000 resamples, seeds nested in games) giving 95% CIs; the +-8-net floor at 274 x 2 is the minimum reportable margin and all confirmatory margins (+14) exceed it; per-type differences (+-13 to +-15) are exploratory only. Fixed decoding temperature and seeds as in Measurement A; the same vLLM build, prompt template and retriever checkpoint in every arm; the static prefixes are byte-identical across episodes so prefix-cache hits are verified from the vLLM logs. Manipulation check precedes confirmatory cells; predictions and margins pre-registered in DESIGN.md before the first confirmatory cell. valid_seen and valid_unseen reported separately (unseen is the natural scene-disjoint supply), plus pooled. Prefill tokens per episode (cached/uncached) and wall-clock per episode logged for the accuracy-cost curve.

### proposal: protocol_bindings_procedure_count
Title: How Many Procedures Before a Cached Prompt Needs a Query: Planting Protocol-Keyed Procedures to Manipulate Procedure Count in ALFWorld
Short Hypothesis: The residual of experience retrieval over a type-agnostic cached prompt is a routing residual: it is positive only when the reader's in-context selection among the P procedures the task distribution spans is worse than the retriever's selection. ALFWorld spans P = 6 and shows no residual; multiplying P by planting protocol-keyed hidden preconditions (P = 6, 24, 96, 288) produces a residual above a threshold P*, and a factorized compiled prompt (six procedures plus one row per protocol) removes it again, so the property that makes a query necessary is the size of the smallest compiled form of the procedure set, not the number of procedures.

Experiments:
1. Wrapper: intercept env.step; maintain per-episode predicates (examined(o), opened-then-closed(r), looked(r), inventory-checked, visited(landmark)); if the action is the protocol's trigger and its prerequisite is unmet, return 'Nothing happens.' without state change; protocol code inserted into the first observation. Define 48 distinct protocols as (trigger in {take, put, heat, cool, clean, use, go to}, prerequisite in a menu of 8 distinct prior actions) minus incoherent pairs; assign codes uniformly to games at each R with a fixed seed. 2. Bank: for each train and eval game and each protocol in force, insert the prerequisite step into the expert action sequence by rule and replay through the wrapped environment; keep verified successes; the retriever indexes goal plus protocol line. 3. Manipulation check: k=0 on unmodified games vs k=0 under R = 1, 274 x 2 seeds; pre-registered escalation if the drop is < 8 net: violations count as episode failure instead of 'Nothing happens.' 4. Confirmatory ladder, each arm 274 x 2 seeds (~30 min): at R in {1, 4, 16, 48}: retrieval k=3, all-P compiled, factorized compiled, six-procedure no-protocol prompt, oracle-routed static; plus length placebo at R = 4 and whole-bank at R in {1, 4}. About 24 arms, ~13k episodes, ~11 h on two A100s. 5. Reader ladder (exploratory): Qwen3-8B on retrieval, all-P and factorized at R in {4, 16, 48}, ~4 h. 6. Compile source ablation: all-P and factorized prompts written by rule (exact by construction) vs written by Qwen3-32B from the bank, at R = 16. 7. Cost: cached vs uncached prefill tokens and wall-clock per episode; accuracy-cost curves per R; note that cached tokens still add per-step decode cost, so wall-clock is reported alongside tokens.

Baselines and Ablations:
Static baselines (cached): all-P compiled prompt; factorized compiled prompt; six-procedure no-protocol prompt (knowledge-free control); oracle-routed single procedure (routing-free upper bound, non-deployable); length placebo (R = 4 content padded with 264 procedures from protocols not in force, matched to the R = 48 prompt length) to separate routing burden from context length; whole-bank arm at R in {1, 4} (all verified items for the game's type and protocol, <= 80 items). Retrieval: goal plus protocol-line query, k=3; ablations k=1, k=7 at R = 48; goal-only query at R = 48 (protocol code absent from the query) to show the query must carry the binding; random-protocol retrieval placebo at R = 48. Ordering ablation: all-P prompt sorted by protocol code vs shuffled. Second reader (Qwen3-8B) on the three main arms.

Falsifiable Predictions:
P1 (positive control) Under R = 1, k=0 success is >= 8 net below k=0 on unmodified games. Falsified by a drop < 8 net (the reader discovers the precondition by trial within the budget); produced by the two k=0 cells; the pre-registered stricter wrapper is then used, and if the drop is still < 8 the study stops and reports the lever inert. P2 (no routing residual at low P) At R in {1, 4}, retrieval minus all-P compiled is <= +8 net. Falsified by a residual >= +8 at R = 4 (the reader already fails to route among 24 procedures), produced by the R = 4 retrieval and all-P cells. P3 (routing residual at high P) At R = 48, retrieval minus all-P compiled is >= +14 net, and the residual is non-decreasing in R. Falsified by < +8 net at R = 48 (the reader routes among 288 cached procedures as well as the retriever, so procedure count is not the property); produced by the R = 48 cells. P4 (not a context-length effect) At R = 4, the length placebo (10k-token prompt with 24 relevant procedures) is within +-8 of the unpadded all-P prompt. Falsified by placebo <= all-P - 8 (the degradation is length, not routing); produced by the placebo cell. P5 (factorization restores compilability) At R = 48, factorized compiled minus retrieval is >= -8 net. Falsified by factorized < retrieval - 8 (the reader cannot index 48 rows either, so the query is necessary at a row count of 48 and the property is table size, not procedure count); produced by the factorized cell at R = 48. P6 (residual is routing, not content) At every R, retrieval minus oracle-routed static is <= +8 net. Falsified by >= +8 at any R (retrieved trajectories carry value beyond the (type, protocol) procedure); produced by the oracle cells. P7 (exploratory, reader dependence) The smallest R with residual >= +14 is smaller for Qwen3-8B than for Qwen3-32B. Falsified by the 8B ladder showing no residual through R = 48 or the same threshold; produced by the 8B cells.

Measurement and Noise Control:
Task success on identical (game, seed, protocol assignment) triples across arms; paired nets with a cluster bootstrap over games (1,000 resamples) and 95% CIs; the +-8-net floor at 274 x 2 is the minimum reportable margin; confirmatory margins are +14 (half the Gate-0 gain). Protocol assignment fixed per R by seed so every arm sees the same codes; codes are random strings so the reader cannot infer content; the wrapper is deterministic. Same decoding settings, vLLM build, prompt template and retriever as Measurement A. Prefix-cache hits verified from vLLM logs for all static arms; cached and uncached prefill tokens and wall-clock logged per episode. Manipulation check first; ladder pre-registered with the threshold prediction (between R = 4 and R = 48) before the first confirmatory cell; per-type and per-protocol breakdowns exploratory.

### proposal: binding_scope_leakage_ladder
Title: Global Fact, Scene Table, or Instance Replay: The Scope of Instance Bindings Sets How Much of a Memory Gain Is Near-Duplicate Leakage and Whether a Static Prompt Can Match It
Short Hypothesis: An experience bank helps on a new task instance only through information that transfers from bank items to that instance; the scope of the instance bindings (global rule, per-scene, per-instance) determines the smallest compiled substitute for retrieval (one sentence, a row table, none) and how much of the retrieval gain is near-duplicate leakage. At instance scope the gain exists only through duplicates of the evaluation instance in the bank and is linear in the duplicate rate with zero intercept; at global scope one compiled sentence matches retrieval and the duplicate rate is irrelevant beyond one item per class.

Experiments:
1. Gate (pre-registered): the scene-scope, s = 1, relocated x 25-step cell must show scene-query retrieval minus type-agnostic static >= +14 net (the positive control shared with the relocation design); if it does not, the ladder is not run and the failure is reported. 2. Construction: three relocation rules applied to the PDDL init of the 274 eval games and of train games in eval scenes; expert trajectories regenerated with the ALFWorld PDDL expert; at instance scope the duplicate is the eval game's own verified success from a first pass by the same reader with the type-agnostic prompt (self-pool style, on-policy), placed in the bank for a fraction s of games chosen by seed. 3. Cells (each 274 x 2 seeds, ~30 min): instance scope: retrieval at s in {0, 0.5, 1}, type-agnostic static, whole-bank at s = 1; scene scope: retrieval at s in {0, 1}, type-agnostic static, table static, whole-bank at s = 1; global scope: retrieval at s in {0, 1}, retrieval with the 20-item one-per-class bank, type-agnostic static, compiled-sentence static, whole-bank at s = 1. About 17 cells, ~9.3k episodes, ~8 h on two A100s. 4. Exploratory: goal-query retrieval at instance scope s = 1 (does goal similarity find the self-duplicate); stale self-duplicate (from the canonical game) at instance scope; per-type breakdown; k=1 at instance scope s = 1. 5. Cost: cached vs uncached prefill per episode; the compiled-sentence and table arms have zero uncached tokens; accuracy-cost curve per scope.

Baselines and Ablations:
Static baselines (cached): type-agnostic six-procedure prompt (no bindings, run at every scope since the games differ); compiled sentence per class (global scope only, ~20 sentences); compiled table per (scene, class) (scene scope; <= 274 rows); whole-bank 80-item arm at s = 1 for every scope (contains the duplicate; information-complete without a query); random-type length placebo. Retrieval: scene-query k=3 (goal plus first observation); ablations: goal-query at instance scope; k=1 and k=7 at instance scope s = 1; 20-item one-per-class bank at global scope vs the full relocated bank; stale duplicate at instance scope. Seeds: the s = 0.5 subset is drawn by seed and the complementary subset is run as a second draw to check that the linear estimate does not depend on which games carry duplicates.

Falsifiable Predictions:
P1 (gate, positive control) At scene scope, s = 1, scene-query retrieval minus type-agnostic static >= +14 net. Falsified by < +8 in that cell; the ladder is then not run. P2 (global scope compiles to a sentence) At global scope, compiled-sentence static minus retrieval (s = 1) >= -8 net. Falsified by sentence < retrieval - 8 in the global-scope sentence cell (the reader applies a concrete trajectory but not a stated rule). P3 (global scope needs one item per class) At global scope, retrieval with the 20-item one-per-class bank is within +-8 of retrieval with the full relocated bank. Falsified by 20-item < full - 8 (a many-shot requirement per class) in the 20-item cell. P4 (scene scope compiles to a table) At scene scope, table static minus retrieval (s = 1) >= -8 net. Falsified by table < retrieval - 8 in the scene-scope table cell. P5 (instance scope: gain is replay) At instance scope, retrieval (s = 1, own earlier trial present) minus type-agnostic static >= +14 net. Falsified by < +8 in that cell (the reader does not exploit even an exact self-duplicate). P6 (linear, zero intercept) At instance scope, retrieval residual at s = 0.5 is within +-8 of half the residual at s = 1, and the residual at s = 0 is <= +8 (control cell; near-entailed by the split and declared as such, not a headline). Falsified by residual(0.5) >= residual(1) - 8 (superlinear: partial duplicates seed a search strategy that transfers to non-duplicated games) or residual(0.5) <= +8 while residual(1) >= +14 (sublinear: the reader trusts duplicates only when they are reliably present); produced by the s = 0.5 cell against the s = 1 cell. P7 (the whole-bank arm does not replace the query at instance scope) At instance scope s = 1, whole-bank 80-item arm <= retrieval - 8. Falsified by whole-bank >= retrieval - 8 in that cell (the reader finds its own trial among 80 items without a query). P8 (exploratory) At instance scope s = 1, goal-query retrieval residual <= scene-query residual - 8; falsified by goal-query within +-8 of scene-query in the goal-query cell.

Measurement and Noise Control:
Task success on identical (game, seed) pairs across arms within each scope; paired nets with a cluster bootstrap over games (1,000 resamples) and 95% CIs; the +-8-net floor at 274 x 2 is the minimum reportable margin; confirmatory margins +14 (half the Gate-0 gain). The s = 0.5 subset is drawn by seed with a complementary second draw so the linear estimate is checked across draws; the same first-pass trajectories are used as duplicates in every arm at instance scope. Same decoding, vLLM build, prompt template and retriever as Measurement A; static prefixes byte-identical with cache hits verified from logs; cached and uncached prefill tokens and wall-clock per episode logged. Gate and predictions pre-registered before the first confirmatory cell; per-type claims exploratory; valid_seen and valid_unseen reported separately and pooled.
