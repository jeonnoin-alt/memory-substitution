Title: Bigger Banks Help Retrieval Only Through Near-Duplicates the Reader Cannot Find in Context: Bank Size x Near-Duplicate Rate on WebShop and ALFWorld
Short Hypothesis: The growth of top-k retrieval's advantage over the whole-bank-in-context route with bank size is a near-duplicate effect. ### proposal: compile_the_statistics_not_the_trajectory
Title: What Retrieval Cannot Carry: Cross-Episode Location Statistics Compiled From the Bank Beat Retrieved Trajectories on Search-Bound Tasks
Short Hypothesis: A compiled artifact can hold a cross-episode aggregate (object -> receptacle location frequencies) that no set of k retrieved trajectories contains. On ALFWorld's search-bound types (pick-and-place, pick-two, look-at-in-light) a ~300-token, type-agnostic, cached cheatsheet compiled by rule from the expert pool recovers at least the Gate-0 retrieval gain on those types (~+10) over no memory at zero uncached prefill. Its value comes from aggregation, not coverage or scaffold: a coverage-matched table built from one sampled trajectory per object class loses most of it, a row-deranged table loses all of it, and the raw 80-item bank in context does not reproduce it unless the table compiled from those same items is added explicitly. Added to the best static arm (Measurement C's static3), the statistic removes the residual that k=3 retrieval keeps over it on the search-bound types (C: ~+9 there); it is not expected to touch the procedure-bound residual (+20..+27), which is reported as the scope boundary, not claimed.

Experiments:
Bank: expert pool (1,465 trajectories). Compiler (rule, no LLM): from each trajectory take the receptacle of the first successful 'take <obj> from <recep>' action; per object class (~30) emit the top-3 receptacle classes with count and percentage; ~300 tokens; identical for every game and type; placed in the instruction slot as a cached static prefix. Aggregation-depth ladder at fixed coverage (replaces the n-trajectory ladder, whose low rungs confounded coverage with depth): cheatsheet_d samples, for every object class c, min(d, n_c) trajectories containing that class and compiles the row from them; d = 1 (one sample per class, every class covered, ~150 tokens, three uniform draws), d = 4 (one draw, exploratory), d = all (the full table). Placebos: shuffled_all (receptacle lists deranged across object classes, identical tokens and format); LLM-prior (Qwen3-32B fills the same format for the same object classes and receptacle vocabulary from its own knowledge, no bank, generated once, token-matched). Whole bank: 80 expert items (~140 tokens each, ~11k tokens, cached) selected by a stated rule - stratified by task type and, within type, to cover every object class at least twice; fixed order per seed; whole-bank_80 + cheatsheet_80 adds the table compiled from exactly those 80 items (~250 tokens). Cells: cell S = the 134 search-bound games (pick-and-place, pick-two, look-at-in-light; 59 unseen + 75 seen) x 8 seeds = 1,072 paired (game, seed) cells per arm; seeds 1-2 coincide with Measurement C's cells. Confirmatory arms on cell S (12, all run fresh in one serving session so every contrast is paired within-session): k0; k3 retrieval (~430 uncached tokens); static3 (C's best static arm, 3 fixed type-conditioned exemplars, ~430 tokens cached); cheatsheet_all; shuffled_all; LLM-prior; cheatsheet_d1 x 3 draws; static3 + cheatsheet_all (~730 tokens cached); whole-bank_80; whole-bank_80 + cheatsheet_80. Exploratory arms at seeds 1-2 (268 cells, floor +-12): cheatsheet_d4; instr_all + cheatsheet_all (type-agnostic twin of the static3 combo, ~700 tokens); cheatsheet_80 alone; k3 + cheatsheet_all (additivity); and cheatsheet_all on the 140 procedure-bound games x 2 seeds (280 cells) against C's stored k0/static3/k3 cells for the scope boundary. Process measure from step logs: distinct receptacles visited before the target object is taken (episodes with no take scored at all distinct receptacles visited); steps per episode. Cost: uncached and cached prefill tokens per episode (static prefixes cached across the arm under vLLM prefix caching; retrieval prefixes uncached), tokens/s per GPU, episodes/min; accuracy-cost curves over uncached prefill. Arithmetic: 12 confirmatory arms x 1,072 = 12,864 episodes + ~1,350 exploratory = ~14.2k episodes; at the rate assumed in the original plan (548 episodes per ~30 min, ~18 episodes/min across two vLLM replicas on two A100s, workers tuned to the queue) ~13 h, plus ~1 h for the two whole-bank arms decoding against an 11k cached prefix: one overnight run, resumable JSONL under nohup. Order: (1) fresh k0 and k3 (drift check against C's stored seeds 1-2 and positive control; the bootstrap half-width on this pair fixes the floor and the margins before any confirmatory arm); (2) cheatsheet_all (headline); (3) static3, shuffled_all, LLM-prior; (4) the three d=1 draws; (5) static3 + cheatsheet_all; (6) the whole-bank pair, last among confirmatory arms so a budget overrun costs P6 and not the headline; (7) exploratory arms on idle replica time. Pre-registration file (arm list, cells, margins, decision rules, stopping rule) committed before step (2).

Baselines and Ablations:
Baseline per the round rule is the best static arm: static3 (C: +12.4 over k0 overall) is re-run on cell S at 8 seeds, and every retrieval number on cell S is reported as k3 (and k7 from C's stored cells at seeds 1-2) minus the best of {static3, cheatsheet_all, static3 + cheatsheet_all}; cheatsheet_all - static3 is reported (does 300 tokens of statistic beat 430 tokens of type-conditioned exemplars on search-bound types). Type conditioning: the cheatsheet is one fixed table for all games and types; static3 is type-conditioned, so its combo has a type-agnostic twin (instr_all + cheatsheet_all). Ablations that attribute the gain: depth at fixed coverage (d = 1 vs all; d = 4 exploratory) - aggregation vs coverage; deranged table - content vs scaffold, with shuffled_all - k0 reported so 'true table helps' is separated from 'wrong table hurts'; LLM-prior table - experience vs pretraining, with the pre-registered covariate of row-level top-1 agreement between the prior and the compiled table; whole-bank_80 with and without its own table - explicit vs implicit aggregation at matched items; k3 + cheatsheet_all - additivity to retrieved procedures (exploratory). The manipulated variable is the artifact (depth, content, source) at fixed format; the search-bound/procedure-bound split is a pre-registered pooled cell, and its contrast (the statistic helps only where search is the bottleneck) is reported from the 2-seed procedure-bound arm as exploratory scope evidence, not claimed.

Falsifiable Predictions:
Decision rule for every 'X - Y >= M on cell S' prediction (floor F = +-6 at 1,072 paired cells; F < M throughout): confirmed iff the paired 95% bootstrap CI excludes 0 in the predicted direction and its upper bound is >= M (the predicted size is not excluded); falsified iff the CI upper bound is < M; otherwise inconclusive and counted against the claim. With F < M a true effect of size M is falsified with probability ~2.5% and a true null is confirmed with probability ~2.5%, so 0 and M are separable. M1 = +10 = the Gate-0 retrieval gain pooled on the search-bound types (A: +15 / +18 / -4.8 weighted by game count; recomputed from stored cells and, if larger, replaced by the fresh k3 - k0 on cell S; fixed at pre-registration). M2 = +7 (two-thirds of M1: the majority of the compiled gain). P1 (headline): cheatsheet_all - k0 >= M1 on cell S. Arm: cheatsheet_all vs fresh k0. Falsified if the CI upper bound < M1 - reachable because nothing forces the reader to use a frequency table. P2 (aggregation, not coverage): cheatsheet_all - cheatsheet_d1 (mean of three draws, draws nested in the bootstrap, F ~ +-6) >= M2 on cell S. Arm: the d=1 draws vs cheatsheet_all. Falsified if the CI upper bound < M2 - reachable if one sampled placement per object class already carries the usable content, in which case the table's value is coverage, not aggregation. Between-draw SD reported; the ordering d1 < d4 < all is exploratory and unpowered (d4 at 2 seeds, F +-12). P3 (content, not scaffold): cheatsheet_all - shuffled_all >= M1 on cell S. Arm: shuffled_all. Falsified if the CI upper bound < M1 - reachable if the reader treats the table as a 'search receptacles systematically' scaffold and ignores rows. shuffled_all - k0 is reported with a pre-registered reading: if shuffled - k0 is reliably negative while cheatsheet_all - k0 is not reliably positive, P3 is not counted as support (it would show a wrong table hurts, not that the right one helps). P4 (experience, not pretraining): cheatsheet_all - LLM-prior >= M2 on cell S. Arm: LLM-prior. Falsified if the CI upper bound < M2 - reachable and plausible, since ALFWorld placements are stereotyped; that outcome means a static prompt with no experience recovers the search-bound retrieval gain and is reported as the informative negative; the pre-registered covariate (top-1 agreement between the two tables) says whether a null is redundancy (agreement high) or the reader ignoring content (agreement low, then in tension with P3). The residual vs k7 (1,010 tokens; C's stored cells at seeds 1-2) and the type-agnostic twin instr_all + cheatsheet_all are reported alongside. P6 (the reader is not an aggregator): (whole-bank_80 + cheatsheet_80) - whole-bank_80 >= M2 on cell S, where cheatsheet_80 is compiled from exactly the 80 items in context, so the information is present in both arms. Arm: the whole-bank pair. Falsified if the CI upper bound < M2 - reachable if the long-context reader extracts the placement statistic from the raw items itself, making the explicit table redundant. cheatsheet_80 alone vs whole-bank_80 is reported (exploratory, 2 seeds); cheatsheet_80 is no longer a rung of the depth ladder, so P2 and P6 no longer share a cell. Predicted paired reduction >= 1.0 under cheatsheet_all vs k0 on cell S; confirmed iff the 95% CI of the reduction lies entirely above 0.5, falsified otherwise (expected half-width ~0.2-0.3 at 1,072 paired episodes, so the rule is decisive).
