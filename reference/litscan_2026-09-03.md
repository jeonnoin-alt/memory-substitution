## Headline findings

1. **Closest collision: EvoAgentBench (arXiv 2607.05202, 2026-07-06). [PDF verified 2026-09-03, supplied by the PI; text extracted to `litscan_raw/evoagentbench_2607.05202.txt`.]** Benchmarks agent self-evolution on a shared 528/267 train/test split across web research, algorithmic reasoning, software engineering and knowledge work, 2 scaffolds, 3 backbones. Methods: Vanilla, **Memento** (retrieve closest retained training case), **ReasoningBank** (retrieve from distilled memory), **GEPA** (evolve one prompt), and a curated "Anchor" reference. Reported (Table 3, per-domain accuracy as mean ± SE over three runs): Anchor† is the only condition positive in every cell (+7.5/+10.5/+5.8 average by backbone). **Corrected from the PDF:** on Qwen3.5-27B the averages are Vanilla 37.5, +Memento 35.1 (−2.4), +RB 41.1 (+3.6), +GEPA 38.7 (+1.2), +Anchor 45.0 (+7.5); on Qwen3.5-397B RB +2.4, GEPA +3.5; on Gemma-4-31B RB +0.4, GEPA +5.7. The earlier '+7 on Qwen backbones' for ReasoningBank came from a web snippet and was wrong. Setup: scaffolds OpenClaw and Nanobot; domains BrowseComp-Plus, SWE-Bench Verified, LiveCodeBench, GDPVal; extractor Claude Sonnet 4.6. **This is the first paper that puts a memory retriever and GEPA side by side on the same training trajectories** — the three-way comparison v2 said did not exist. What it does *not* do — now confirmed from the PDF: the conditions are exactly Vanilla, +Memento, +RB, +GEPA, +Anchor†, and GEPA is described as 'the only no-retrieval evolution condition'; there is no combined optimizer+memory condition, the word 'token' does not occur (no token matching), there is no paired test or bootstrap (mean ± SE over three runs), and Support@10 is the only retrieval-budget statement. v4 must lead its collision check with this paper and position S as the quantity EvoAgentBench's table cannot yield.
2. **Structural precedent for the ratio: Experience Distillation (arXiv 2607.21051, 2026-07-23).** "In-context learning ... gains disappear once that experience is removed from the context"; context distillation into weights retains ≥64.8% of the ICL gain, plain SFT only 3.8%. This is exactly the "what fraction of the in-context gain survives in a second container" quantity — with weights as the second container instead of an optimized instruction. v4 should name this as the nearest measurement object and state that S uses a container that is cheaper to serve and needs no gradient access.
3. **The compile prediction now has published directional support (and therefore less novelty):** skills (distilled SKILL.md) beat Workflow Memory by 6.06pt in matched comparison, and 65.7% of skill benefit is procedural anchoring rather than fact injection (arXiv 2608.14036, 2026-08-14); model-generated skills help on average but hurt 25% of cases (arXiv 2605.23899); a single one-shot rewrite with the full training signal matches 10-iteration refinement within 0.2% (arXiv 2606.30775). None of these compare a compiled artifact against per-instance retrieval at matched tokens, and none involve an optimizer; but "compile once" is no longer a surprising direction. Prediction 3 should be re-pitched as a *quantified* claim (within TOST margin at matched tokens), not as a surprise.
4. **Whole-bank-in-context baseline is now demanded by the literature, not only by v3's reviewer:** EvoMemBench (arXiv 2605.18421) finds long-context baselines "remain highly competitive" against 15 memory methods. v4 adds M_all.
5. **Optimizer-failure risk is quantified:** "Prompt Optimization Is a Coin Flip" (arXiv 2604.14585) — 49% of 72 runs below zero-shot; helps only when the task has exploitable output structure. This sharpens risk R2 and motivates reporting I1 vs I0 as a prerequisite result with a pre-registered branch.
6. **Memory-harm results keep accumulating** (arXiv 2604.27003: retrieval pollution / context competition / dilution; arXiv 2607.28272: raw memory injection 70.1% < no-memory RL 76.4% on ALFWorld), and this program's own pre-registered study (proposal ①, 2026-08) found the ExpeL bank's effect to be TOST-equivalent to zero on Qwen3.5-27B (+0.6pt) and +7.7pt on gpt-oss-120b. Consequence for v4: the agent must be chosen where memory has a measurable effect, and the precheck gate must be set from measured numbers, not from the literature's ≥10pt.
7. **v2's retraction of five IDs was wrong.** ActMem (2603.00026), MAS-PromptBench (2606.23664), TERMS-Bench (2605.13909), MemAPO (2603.21520) and StructMemEval (2602.11243) all exist. The 2026-08 search failed, not the citations. TERMS-Bench did run GEPA as a prompt-ablation (frozen base prompt + one appended strategy patch, Claude reflector) to test whether prompt engineering saturates the benchmark — the "use an optimizer as the control" move the v1 reviewer described. MemAPO is the opposite coupling direction (memory *inside* the optimizer). v4 reinstates all five with their actual roles.
8. **Parametric third container is now a live literature:** TMEM fast-LoRA memory (arXiv 2606.04536), experience internalization (arXiv 2606.04703), LoRA-SFT vs retrieval (arXiv 2603.18272), and Experience Distillation (above). The v1 reviewer's LoRA-arm request is therefore answerable with a cited recipe rather than refused.

## What was NOT found (residual risk)
- No paper computes a residual/substitution ratio for memory after instruction optimization on matched episodes.
- No paper combines a prompt optimizer with retrieved procedural memory in a factorial (I×M) design with token matching.
- OpenReview for ICLR 2027 is not yet visible (deadline after this scan); NeurIPS 2026 camera-readies may surface in October. A "GEPA + memory" ablation could sit in an appendix of a systems paper; the search cannot exclude that.
