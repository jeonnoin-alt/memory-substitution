The new filter

What the entailment check looks for

This stage was added after the previous topic run, where judges kept finding predictions that could not lose. An Opus checker reads every prediction and asks two literal questions: is the falsifying outcome reachable under the arms the proposal actually names, and is it distinguishable at the noise the proposal itself states? Each prediction gets one of four labels, and the proposal is sent back if its headline prediction is anything but open.

openThe falsifier can happen and the design could see it. This is the only acceptable state.
nearFalsification needs a mechanism the design never names, controls, or measures.
entailedThe falsifying outcome cannot occur. The prediction restates how the experiment was built.
unresolv.The decision band is narrower than the stated confidence interval, so neither answer can be reached.

Across the 45 proposals the checker labelled every prediction individually. The small four-colour bar on each proposal below is that distribution, and the number beside it is how many predictions the proposal makes.

Handover

Picking this up

Everything is committed to the repository. Agent identifiers for every stage are stored next to the jobs, so any stage can be re-collected without re-running it.

  1. 01
    Clear the revision backlog.

    Twenty-three proposals still need their flagged predictions rewritten. The prompts are already emitted and waiting; only the model call is missing. This is the decision that unblocks everything downstream.

  2. 02
    Re-run the entailment check on the revised text.

    A revision is only accepted if the headline prediction comes back open. The ten finished revisions have not been re-checked yet.

  3. 03
    Fold Measurement C into the three briefs.

    The retrieval residual over the best fixed prompt is now measured, not assumed. Any proposal whose margins were set against an assumed baseline needs those margins restated before it is judged.

  4. 04
    Judge, then escalate.

    One Opus judge per proposal, two more only for the promising ones, then rank and take the top few forward.

  5. 05
    Decide the next GPU job.

    Both A100s have been idle since Measurement C finished. The standing rule is to keep them saturated, so this needs an assignment.
